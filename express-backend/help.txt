# Backend Design Mindset

Before writing any code, ask yourself these questions:

## 1. What is the business?

Example:

> Interview Scheduler

Not:

> Express project

Not:

> MongoDB project

Always think about the **business** first.

---

## 2. Who are the users?

Example:

```text
Admin

Recruiter

Interviewer

Candidate
```

These become your **roles**.

---

## 3. What are the main entities?

Don't think in terms of controllers yet.

Think in terms of **real-world objects**.

Example:

```text
Candidate

Interview

Job

Employee

Department

Feedback
```

These usually become your database collections.

---


```http

GET /interviews
```

# Business Rules

Now ask:

"What rules exist?"

Example

```text
Candidate cannot have two interviews at the same time.

Interviewer cannot have overlapping interviews.

Interview duration must be positive.

Past interview cannot be edited.

Only Recruiter can schedule interview.

Only Interviewer can submit feedback.
```

These become service logic.

# The Design Process I Follow

Whenever I start a new backend, I use this checklist:

```text
1. Identify users
2. Identify roles
3. Identify entities
4. Design relationships
5. Design collections
6. List features
7. Design APIs
8. Define business rules
9. Identify validations
10. Think about edge cases
11. Decide authorization rules
12. Think about scaling
```

I don't write a single line of code until I can answer those questions.

# What We'll Build Together

Instead of building another "User CRUD" project, I'd like us to build something that resembles a real production system.

Given your recent work, **an Interview Scheduler** is a great choice because it naturally includes:

* Authentication & Authorization
* CRUD operations
* Relationships (`populate`)
* Pagination, filtering, sorting
* File uploads (resumes)
* Email notifications
* Scheduling logic
* Validation
* Logging
* Audit history
* Dashboard statistics
* Search
* Status workflows

It touches almost every important backend concept you've learned, making it an excellent capstone project.

## My teaching plan

We'll do this in phases:

1. **Requirements analysis** (no code)
2. **Database design (ERD)**
3. **API design**
4. **Folder architecture**
5. **Implementation model by model**
6. **Advanced features (notifications, reports, etc.)**

This mirrors how backend projects are typically planned and developed in professional teams, where design decisions come before implementation.
